# Design

The template as it is now. The reasoning, and how it got here, is in
[decisions/](decisions/); a change to the design updates this page and adds a
decision.

## Purpose

A knowledge base a person creates from this repository, registers in irori and
initialises with `init`. Agents compile what the person reads, decides and
makes into pages with citations and keep them consistent; irori shows the
pages, checks them against one declaration and generates their indexes. It
follows the loop of Karpathy's LLM wiki (ingest, query, lint) in the
[Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format)
0.2 ([ADR 002](decisions/002-okf-bundle.md)).

## Principles

1. **One owner per fact** ([ADR 010](decisions/010-a-small-contract-over-declared-data.md) D1).
   What may exist is declared in `.property/property.json`; irori's behaviour
   is irori's documentation; procedures are skills; invariants and boundaries
   are `AGENTS.md`; starting and extending is `README.md`.
2. **Extend by declaring.** A type, a relation or a type's folder is one entry
   in the declaration. Skills read the declaration rather than naming types or
   folders.
3. **irori is the runtime.** The template needs irori 0.2.66 or later, uses
   `irori index` and `irori check`, and restates neither.
4. **Knowledge is the center** ([ADR 004](decisions/004-knowledge-centered-layers.md)).
   Criteria, facts and reasons are pages, where they carry sources and can be
   checked and shared. Skills apply them; `contents/` holds the files they are
   about.

## Layout

```text
AGENTS.md                template-owned: the contract
README.md                the front page
.agents/skills/          template-owned: init ingest query lint review journal promote vocabulary
.property/property.json  knowledge-base-owned: the declaration
.irori/                  knowledge-base-owned: scope.json, notes.json, templates/
index.md                 the root index (okf_version 0.2)
journal/<year>/          journal pages
wiki/                    every other type, flat until an index passes about 150 entries
contents/<mount>/        connected by irori, never committed: Inbox/ source/ output/
docs/                    this repository's records; init removes it
```

The knowledge layer sits at the repository root
([ADR 008](decisions/008-knowledge-at-the-root.md)). irori classifies
`AGENTS.md`, `README.md` and dot folders as schema, `contents/` as contents and
everything else as knowledge.

## The declaration

`.property/property.json` is the ontology
([ADR 009](decisions/009-the-ontology-is-the-declaration.md)): properties with
their kinds, the keys every page requires, nine types, four relations and the
names to avoid. Each type has a meaning, the keys it requires, its index
`heading` and its `folder`. Each relation has a meaning, the types it goes
`from` and what it points `to`.

| Types | Folder |
| --- | --- |
| `journal` | `journal` |
| `concept`, `decision`, `policy`, `reference`, `artifact`, `person`, `org`, `project` | `wiki` |

| Relation | From | To |
| --- | --- | --- |
| `about` | any | `person`, `org`, `project` |
| `part_of` | `person`, `org`, `project` | `org`, `project` |
| `uses` | any | any page |
| `same_as` | `person`, `org`, `project` | a URL |

irori reads everything but `folder`, which only agents use. The vocabulary
changes only through the `vocabulary` skill
([ADR 003](decisions/003-vocabulary-review.md)): one evidenced proposal at a
time, agreed by the person.

## Pages and indexes

Every page has frontmatter with `type` and the keys the declaration requires;
its path is its identity; `generated` is the last change. Every folder with
pages has an `index.md` generated by irori (irori
[ADR 028](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/decisions/028-generated-indexes.md));
the only hand-written index text is a folder line's description.

A file in `contents/` that matters has a page: `reference` for one someone else
wrote, `artifact` for a deliverable made here. A task that ends in a decision
has a `decision` page.

## Skills

| Skill | Does |
| --- | --- |
| `init` | once: the owner's identity page, `.irori/notes.json`, the indexes; removes `docs/` |
| `ingest` | arrived material and unregistered deliverables into pages |
| `query` | answers with citations; files a useful answer back as a `concept` |
| `lint` | the health check after `irori check`; fixes only what is mechanical |
| `review` | looks back over a period with the person: what waits, what is open, what is due, what should connect ([ADR 011](decisions/011-reading-the-knowledge-base-again.md)) |
| `journal` | appends a person's dated record |
| `promote` | copies a page into another knowledge base as a pull request |
| `vocabulary` | changes the declaration by agreed proposals |

## Ownership

`AGENTS.md` and the shipped skills belong to the template and can be replaced
by a newer copy. The declaration, the pages and `.irori/` belong to
the knowledge base. A knowledge base's own rules are `policy` pages.

## Left to the user

- **Category.** `personal`, `team`, `organization` or any name is a label;
  the template attaches no rule to it. A knowledge base that wants pages
  confirmed before they count writes a policy and uses `verified`.
- **Team and organization operation.** Who reviews what, and when, is not
  designed here. `promote` and `verified` are the only shared mechanisms.
- **Vocabulary growth.** The seed is small on purpose; types such as `repo` or
  `product` come through `vocabulary` when pages need them.
